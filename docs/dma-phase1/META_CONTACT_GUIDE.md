**Document Type**: Operational Guide
**Version**: 1.0

## Overview

This guide explains how to submit Meeshy's application to Meta's WhatsApp DMA Interoperability Program. As of November 2024, this is a structured process with specific channels and requirements.

---

## Step 1: Determine Eligibility

Before contacting Meta, verify that Meeshy meets basic requirements:

### Eligibility Criteria

- ✅ **Legitimate messaging service** - Meeshy is a messaging platform (not spam/malware)
- ✅ **EU-based operations** - Meeshy operates in/targets EU users
- ✅ **Security commitment** - Ready to implement Signal Protocol
- ✅ **Financial capacity** - Can afford registration fees (~€20-50k estimated)
- ✅ **Technical capability** - 5+ developers available for implementation
- ✅ **Legal standing** - Registered company with clear governance

**If YES to all**: Proceed to Step 2

---

## Step 2: DMA Interoperability Portal

### Primary Contact Method

**URL**: https://www.whatsapp.com/interoperability/

**What You'll Find**:
- Official DMA documentation
- Application portal

- News and updates

### Accessing the Portal

1. Go to https://www.whatsapp.com/interoperability/
2. Click **"Apply Now"** or **"Request Interoperability"**
3. Sign up for a developer account (if you don't have one)

5. Upload application documents

## Step 3: Required Documents for Application

Prepare all documents before submitting:

### Mandatory Documents

1. **Company Registration Certificate**
   - Official business registration
   - EU jurisdiction proof
   - File: `company_registration.pdf`

2. **Meeshy Service Description** (Use our document)
   - File: `MEESHY_COMPANY_OVERVIEW.md`
   - Convert to PDF: `meeshy_service_description.pdf`

3. **Security Architecture Document**
   - File: `SECURITY_ARCHITECTURE.md`
   - PDF: `security_architecture.pdf`

4. **Technical Compliance Statement**
   - File: `TECHNICAL_COMPLIANCE_CHECKLIST.md`
   - PDF: `technical_compliance.pdf`

5. **Signal Protocol Implementation Plan**
   - File: `SIGNAL_PROTOCOL_PLAN.md`
   - PDF: `signal_protocol_plan.pdf`

6. **Privacy Policy**
   - Current Meeshy privacy policy
   - Must address data minimization
   - Must include Signal Protocol commitment
   - File: `privacy_policy.pdf`

7. **Terms of Service**
   - Must be compliant with DMA requirements
   - File: `terms_of_service.pdf`

### Recommended Supporting Documents

1. **Security Audit Report** (if available)
   - Independent security assessment
   - File: `security_audit.pdf`

2. **GDPR Compliance Certificate**
   - Privacy Shield or DPA signed
   - File: `gdpr_compliance.pdf`

3. **Bank Verification**
   - Proof of financial stability
   - File: `bank_certificate.pdf` (confidential)

4. **Insurance Certificates**
   - E&O (Errors & Omissions)
   - Cyber liability
   - Files: `insurance_*.pdf`

### Checklist Before Submission

- [ ] All documents in PDF format
- [ ] File names are clear and descriptive
- [ ] Documents have no confidential info that shouldn't be shared
- [ ] PDF file sizes <10 MB each
- [ ] Total submission <50 MB
- [ ] All contact information accurate
- [ ] Legal contact authorized to sign
- [ ] English language (if original is different)

## Step 5: Submission Process

### Via DMA Portal

1. **Create Account**
   ```
   Email: legal@meeshy.com
   Password: [Strong password]
   2FA: Enable (phone number or authenticator)
   ```

2. **Start Application**
   - Click "Start New Application"
   - Organization: Meeshy
   - Service: Meeshy Messaging
   - Contact: [Your legal contact]

3. **Upload Documents**
   - Drag and drop or click to upload
   - Recommended order:
     1. Company registration
     2. Service description
     3. Privacy policy
     4. Security architecture
     5. Signal Protocol plan
     6. Supporting documents

4. **Complete Form**
   - Fill all required fields
   - Double-check information
   - Review legal commitments

5. **Review Submission**
   - Read summary
   - Verify all documents present
   - Check contact information

6. **Submit Application**
   - Click "Submit Application"
   - Save confirmation number
   - Check email for submission receipt

## Step 6: What Happens After Submission

### Expected Timeline

```
Day 1-3: Submission confirmation email
Day 5-10: Initial completeness review
Day 10-21: Detailed technical review
Day 21-35: Meta contacts you with feedback
```

### Possible Outcomes

**Option A: Approved** ✅
- Meta provides Reference Offer
- You sign agreement
- Technical integration begins (Phase 2)
- Timeline: ~4 weeks from submission

**Option B: Approved with Conditions**
- Meta approves but requires specific terms
- Additional security requirements
- Timeline: ~4-6 weeks

**Option C: Request for Information**
- Meta needs clarification
- You provide additional docs/info
- Resubmit
- Timeline: +2 weeks

**Option D: Rejected**
- Rare, but possible if not meeting baseline criteria
- Feedback on reasons
- Option to reapply with improvements

## Step 8: Communication After Approval

### Reference Offer & Terms

When Meta approves, you'll receive:

1. **Reference Offer PDF**
   - 20-50 pages
   - Legal terms & conditions
   - Technical requirements
   - Financial terms
   - Timeline expectations

2. **Terms Summary**
   - Commitment to Signal Protocol
   - User data minimization rules
   - Interoperability requirements
   - Security audit commitments
   - SLA requirements (likely 99.5%-99.9%)

3. **Signature Process**
   - Your legal team reviews
   - Meta sends via DocuSign
   - You sign electronically
   - Process takes ~1-2 weeks

### Key Commitments You'll Make

- ✅ Implement Signal Protocol
- ✅ No backdoors or key escrow
- ✅ 99.5%+ uptime SLA
- ✅ Respond to security incidents <24 hours
- ✅ Allow Meta security audits
- ✅ Pay usage fees (likely per-message or flat fee)
- ✅ GDPR/privacy compliance
- ✅ Regular compliance reporting

### Technical Contact Point

Once agreement signed:

**Meta DMA Technical Support**: [Email provided after approval]
- XMPP server details
- Test vector access
- Staging server credentials
- Integration support
- Go-live coordination

## Step 9: Questions to Expect from Meta

Be prepared for Meta to ask:

### About Your Service

1. **How many users do you have?**
   - Answer: [Your numbers, be honest]
   - Meta wants to understand scale

2. **What countries are you in?**
   - Answer: EU + [others]
   - Important for compliance scope

3. **What's your business model?**
   - Answer: Freemium with optional premium
   - Meta wants to ensure sustainable business

### About Security

4. **Why Signal Protocol?**
   - Answer: Required for DMA, gold standard in E2EE
   - This is not a question, you must use it

5. **How do you manage keys?**
   - Answer: Refer to SECURITY_ARCHITECTURE.md
   - Keys stored encrypted, never in plaintext

6. **Have you been audited?**
   - Answer: Yes/No + plan to be audited in Phase 3
   - Shows commitment to security

### About Interoperability

7. **What happens if service goes down?**
   - Answer: Failover to backup (RTO 5 min, RPO <1 min)
   - Meta wants 99.5%+ uptime

8. **How do you handle abuse/spam?**
   - Answer: Rate limiting + user reporting + Meta collaboration
   - Important for user protection
